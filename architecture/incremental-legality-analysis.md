# Incremental legality analysis

The authoritative engine worker executes commands and validates selected action references. It does not run background priority affordability or inspector payment searches. `isolated-priority-analysis.js` captures the local operation journal through the authoritative queue, shares the already compiled WebAssembly module, and launches `priorityAnalysisWorker.js` with its own engine instance. Capture and message serialization still run on the command worker; engine replay, legality enumeration and inspector payment searches run in the child.

Each immutable priority job enumerates source cards in this order: lands in hand, other cards in hand, battlefield, graveyard, exile, library tops, command zone, sideboard, planar sources and stack sources. The complete game remains available to each query: source scoping does not remove mana sources, targets, cost modifiers, grants or restrictions. Global special actions have a separate candidate. In team priority, each eligible player's candidates are included.

A source has its own resumable mana-search session. Completed candidates append their confirmed actions to a cumulative menu. Unfinished candidates rotate to the back of the queue. Each worker step yields to its event loop and publishes `analysis_complete: false` until every candidate completes. This is not a hard wall-clock bound for all native code: an individual synchronous check can still be expensive, but it cannot occupy the authoritative command worker. There is no two-second escalation to a large foreground search slice.

The runtime retains previously confirmed availability per priority player while a new mana search is pending. A presentation-only pass assumes mana is available but still recomputes timing, zones, targets, permissions and non-mana costs. Only actions that also exist in the previous cache are displayed provisionally; new actions wait for confirmation. Each completed source replaces its provisional entries, including negative results. Timing-ineligible actions remain hidden without erasing their last mana result, so passing through combat does not discard main-phase affordability. Completed local worker results update this cache through the private journal, and native runtime branches own independent cache copies. Selecting any action from an incomplete menu reruns authoritative source legality with ordinary mana checks; presentation assumptions never authorize execution.

The parent accepts results only for the active worker generation and current game/perspective identity. Game mutations terminate busy obsolete workers, including workers inside a synchronous WASM call. A worker that explicitly reports idle is reused across snapshots; its WASM instance and unchanged card registry remain loaded. New registrations replay in their original order without rebuilding the runtime. Each analysis works on a native branch; the next replay resumes the canonical branch before applying further operations. Outstanding inspector requests prevent reuse until finished, and disposal terminates even idle workers. Results carry the visible revision and a monotonic publication sequence. The UI merges partial results, preserves live continuation undo controls, and keeps automatic passing conditional on a complete menu. Selecting an advertised action uses a structured action reference; the authoritative engine independently checks it against the live game, without importing the analysis worker's menu or trusting its indexes. Multiplayer serialization preserves these references when a fresh authoritative snapshot has only an incomplete menu; a missing action in a complete menu is still rejected.

Inspector requests use the same isolated snapshot and wait for its complete priority menu, so their action indexes describe that menu. Requests are deduplicated and resolved on cancellation/error; they never hold the authoritative queue waiting for analysis. Non-priority decisions do not start inspector jobs. Custom drafts, source/artifact registrations, reads, rejected operations, hidden-information inputs and native branch operations are included in the private local journal. Runtime branch handles are translated during replay. Payment options and target previews use the same complete local transport. The only wire checkpoint used in initialization is the empty constructor state, before any gameplay operations, to align allocator origins; live state is never reconstructed from a wire checkpoint for these analyses.

## Verification

- Native `priority_analysis_tests`: land-first partial publication, exact final action-set equivalence including Warp, cumulative results, unchanged priority, and invalidation after mutation, perspective change or cancellation.
- `priority-analysis-scheduler.test.js`: isolated dispatch, stale/cancelled capture rejection, inspector lifecycle, partial merge, live undo preservation and monotonic restart ordering.
- `incremental-priority-worker.browser.test.mjs`: actual WASM workers with multiple Nova Hellkites, Magmatic Hellkites, a hand land, Icetill Explorers and a graveyard land. Injects a 1.5-second synchronous child-worker stall; verifies command-worker savepoint operations and a land action passed through multiplayer serialization remain responsive and the full menu matches synchronous enumeration.

The local replay transport requires rebuilding the frontend worker bundles and uses the existing WASM runtime-savepoint APIs. Engine changes require their own WASM rebuild. The transport does not modify authoritative cost payment or the mana-production evaluator.

## Recorded validation (2026-10-03)

The optimized WASM browser regression matched ten actions with the synchronous reference menu. Two local runs measured 1,013–1,988 ms from checkpoint import to the first land highlight with a cold worker and 10–23 ms with the reused worker. During an injected 1,500 ms analysis-worker stall, savepoint operations took 3–5 ms and multiplayer-serialized land dispatch took 43–85 ms. Replaying the already-used land reference was rejected. These are local Chromium regression measurements, not a replay of the user's multiplayer recording or an end-to-end peer/ZKP benchmark. Initial cold startup is still noticeable; snapshot copying and legality costs can still grow with game complexity. Three native priority-analysis tests and 44 JavaScript scheduling/command-routing tests passed.

## Complete local analysis state (2026-10-03)

The multiplayer resync format is a public projection and is not a complete local analysis snapshot. Besides subtype choices and restricted mana, it omits such inputs as activation/exhaust usage, event history, live executable abilities and temporary permissions. Maintaining a second handwritten list of legality inputs would reproduce this class of failure as engine fields are added.

`local-analysis-replay.js` records engine calls at the runtime boundary, including their original arguments and whether they failed. Child workers replay an immutable prefix and retain a native runtime savepoint, which clones the complete game state and live continuations. Subsequent analyses restore that canonical state and replay only new operations. Preview writes never become canonical. A full session uses its own branch handles; expired handles cannot alias the analysis savepoint. If all native branch slots are occupied, the replica rebuilds from the journal instead of losing session branches. Unexpected replay failures stop analysis and report an error.

The journal stays within local workers. It contains private inputs and must never be included in peer resync, public audits or relay messages. Public checkpoint omissions can still affect multiplayer resync itself; this change removes that format from local highlighting, inspector, payment and target analysis. A newly created or forcibly restarted child must replay the session from its beginning; journal storage and cold replay cost grow with session length.

Validation includes native WASM fixtures proving that checkpoint import incorrectly restores used Exhaust and once-per-turn abilities while local replay preserves the exact menu, transport tests covering omitted state categories and branch handling, real auxiliary-worker tests for target previews and pending payment alternatives, and the real browser stall regression. The final targeted run passed 69 unit/native tests and 5 browser checks. The browser run measured 251 ms cold and 4 ms warm to the first land highlight; savepoint commands took 0.7 ms and land dispatch 19 ms during the injected 1,500 ms analysis stall.
