# Trigger definitions and acquisitions under typed text changes

This is a source-only prerequisite. It admits no complete card body and every
new contract remains unrun. No compiler probe, build, formatter, engine run,
corpus run or test execution was used.

## Definition owner

The compiler finalizer writes `ResolutionProgram::trigger_definition` for each
root triggered ability after program rebuilding and link finalization. Its
version-two namespace is SHA-256 over the complete typed definition graph plus
the authored root occurrence. The activation finalizer uses the same normalized
graph with a separate domain prefix. Both generated root stamps are cleared from
the cloned input before hashing, including composition-loss metadata, so repeated
finalization is stable. The existing transport-owned graph walker canonicalizes
actual CardId newtypes to first-encounter ordinals, including nested token
definitions and references; aliases, root references and ordinary numeric values
remain distinct. Root linked-face allocation and first-printing metadata are
excluded. This typed schema conversion does not invoke the engine, parse Oracle
text, infer JSON property names or mutate the executable definition. Equal printed abilities
have different occurrences. The stamp is frozen with the original definition;
runtime words, labels, Debug output and donor lookups do not reconstruct it.

Compiler first-draw pair construction uses the same typed graph normalization
before freezing its separate version-two definition stamp. The established
frontend producer/consumer group owner supplies ephemeral proof of the generated
inputs; pair numbers and shared/distinct definition relationships survive
normalization. The proof flows directly from that construction owner to the root
stamp finalizers and is never recovered from a runtime source, display, or donor.
Eisenhorn's nested token allocation therefore cannot enter either its first-draw
pair stamp or its root trigger stamp. Re-finalization yields the same identities.

Other retained linked-exile and native definition stamps remain opaque, immutable
inputs. A typed opaque dependency holds the new trigger stamp while its ordinary
program continues to execute under the existing owner. Activation history keeps
its explicit version-one typed namespace fallback in this case; no stronger
canonical proof or new text-domain clearance is claimed for that fallback.

Native authors explicitly supply the full trigger occurrence through
`with_trigger_definition`. The proof covers matcher, program, choices and
condition. Missing native proof remains a text-change hold. Nested quoted
compiler triggers still lack a typed occurrence-path finalizer and are also
held. A parent trigger's stamp never supplies its nested trigger's proof.

The optional stamp survives program mapping, instruction replacement and
compatible append. Composition with unknown or different nonempty owners
clears the stamp and retains `unavailable_trigger_definition`; even a later
append to an empty composite cannot invent a new identity. Explicit native
authorship can supply a complete new stamp. This completeness flag only gates
identity readers; it does not disable ordinary legacy program execution.

## Acquisition owner

`CalculatedAbilities` pairs each stamped definition with the exact host
`ObjectId` and existing `AbilityOrigin` before first trigger discovery. Printed
slots, registered grants, level grants and copied/replaced text keep their
existing origin owner. Runtime rebinding uses the receiving host and the real
grant/copy occurrence. It does not borrow a donor's current origin. A new
object incarnation or a different typed face acquires a different identity.

`Trigger` retains this runtime acquisition outside its matcher model. Its
immutable text-change cache includes the acquisition, so two abilities sharing
a matcher but carrying different bodies or acquisitions cannot cross-contaminate
identities. Captured triggers and stack entry identities remain unchanged.
Layer-3 root triggers require both definition and acquisition evidence; quoted
future grants require definition evidence and bind only when actually acquired.

The legacy structural trigger hash remains the execution owner for unstamped
definitions. This change does not freeze that hash to admit text edits. Default
identity metadata is omitted from Debug as well as serialized programs, so it
does not incidentally change a legacy nested-program hash. The existing
first-event-per-turn predicate continues to examine retained event history;
fire-count, limited-instruction and resolution-count history use the preserved
acquisition identity.

## Compatibility boundary

New serialized root definitions carry `trigger_definition`; historical programs
omit it and decode to unavailable identity evidence. An incompatible composite
may additionally encode `unavailable_trigger_definition: true`. Both fields are
omitted by default and the core effect mapper carries them across phase and
artifact conversions. Compiler-generated full definitions and audit hashes
therefore change. Integration requires the authorized artifact 7 / audit 20
gate; older artifact/audit claims must not be accepted as equivalent new
definitions. This increment does not itself edit those version constants.
The first-draw construction migration changes definitions for God-Eternal Kefnet,
Inquisitor Eisenhorn, Keranos, God of Storms, Primitive Etchings and Rowen. Of those
frozen bodies, Eisenhorn contains the allocation-dependent embedded token body;
all five intentionally acquire the new construction namespace. Existing native
pair IDs and already acquired runtime links are preserved after construction.

Acquisitions are runtime-only and are not an added public snapshot field.
Native object snapshots retain the bound trigger and the paired origin;
public claims strip both executable abilities and origin evidence. Native
RuntimeSavepoint cloning retains captures, histories and the object incarnation.
Accepted genesis reconstructs acquisitions from exact definitions and origins.
There is no new global identity allocator or checkpoint-schema bump.

## Authored contracts, all unrun

- Core metadata mapping, replacement, compatible append, incompatible/unknown
  composition, empty-composite reappend, historical omission and serde round trip.
- Compiler repeatability, equal printed occurrences, root and nested allocation
  exclusion, graph aliases/root references, unchanged ordinary numbers,
  typed-face changes and different executable bodies.
- First-draw/token pair and trigger equality across allocation histories and
  repeat finalization; direct/artifact witnesses for all five migrated bodies;
  presentation-only mutation and independent native/opaque identity negatives.
- Ordered and repeated rewrites, old capture versus current wording, shared
  matcher with different programs, independent registered grants, new object
  incarnation, copied definition, replaced face, expiry and preserved history.
- Missing definition/host holds, definition-only future grants, runtime snapshot
  retention, public snapshot stripping and exact native RuntimeSavepoint restore.
