# Token word roles: ordinary description increment

The ordinary described-token increment is published in draft 862 under artifact 8 /
public digest 4 / audit 21. Its schema fingerprint includes token-role metadata
and derived names; no artifact or signed evidence was regenerated. See
`card-failure-token-role-integration.md`. The subsequent predefined profile increment
changes additional executable names and definitions and requires a separately
coordinated admission decision; it does not assign or publish a new version.
All twelve text-changing cards remain held; every authored scenario remains unrun.

## Creating instruction versus existing token

`CreateTokenEffect::text_roles` records explicit versus subtype-derived name,
authored versus rules-implied color/subtype fields, and the exact ordered ability
occurrences. Missing old metadata stays unknown. It is never inferred from a
finished token name, its abilities, a renderer, or Debug. Native authors can
supply the typed evidence. Fresh native encoding and model materialization carry
it in both directions.

The ordinary description frontend supplies these facts when it reads the actual
name and characteristic clauses. One shared lexical projection retains quoted
rule slices separately from the outer description. Name spans and appositive
prefixes are excluded from characteristic words; quoted subtype, color, supertype,
template-name and ability-name words cannot become the token's characteristics.
Vehicle color values and the legendary flag are carried explicitly through the
shape and lowerer. Original quoted slices still reach the rule/granted-ability
owner. A later explicit name clause updates the typed name role. Postnominal
color facts distinguish an enumerated color list from “all colors.” Legacy
reminder merges that add unproven definition facts mark ability-word provenance
unrecorded while retaining independently proven name/characteristic roles. The
explicit create-clause and quoted-ability owners pass authored facts directly;
their broad reminder keyword guesses are cleared, so the complete keyword/grant
parser owns quoted keywords. Both the early intrinsic keyword probes and the
later outer reminder merge use the same name-free outer projection.

For a described future token, the program visitor rewrites only fields whose
roles permit it. It retains template CardIds, explicit names, mana symbols,
chosen runtime values, static instance IDs, link identities, targets and every
entry/cleanup flag. Derived names come from an explicit typed spelling table,
including punctuation and compound subtypes, followed by `Token`. Creation
recomputes that name after applying a captured chosen subtype. The object's
later layer-three owner changes its type line and rules text while preserving
its existing name and actual colors. Spell copying continues to capture the
pre-text token instruction.

The presentation owner uses the same retained name/color roles. A token explicitly
named `Elf` keeps a `named Elf` clause even when it is also an Elf. An enumerated
five-color list is not rendered as “all colors,” which would erase word roles.
Presentation never supplies runtime execution evidence.

## Exact migration and remaining domains

Old ordinary templates often named a token only `Elf`, `Beast`, or `Snake`.
Under CR 111.4 their derived names are `Elf Token`, `Beast Token`, and `Snake Token`.
This changes executable definition data and name-sensitive outcomes, even when
no text-changing spell is involved. In currently proposed frozen bodies, the
inspected ordinary shared route includes Adipose Offspring (`Alien Token`),
Baloth Cage Trap (`Beast Token`), Cobra Trap (`Snake Token`) and Oni-Cult Anvil
(`Construct Token`). Complete creature descriptions now bypass compact Squirrel,
Elephant, Wall, Astartes Warrior, Dragon Egg and Eldrazi Spawn/Scion shortcuts.
That preserves their actual name, color, supertype, subtype and ability clauses;
a Wall description without defender does not acquire defender. This closes the
same known naming boundary for Camellia, the Seedmiser (`Squirrel Token`),
Belisarius Cawl (`Astartes Warrior Token`) and Brood Birthing (`Eldrazi Spawn Token`).
Spawn/Scion are not predefined-token rules in CR 111.10. Their fully described
instructions own the quoted sacrifice-for-mana ability. Both sentence-planning
entrances now pass that complete quote to the grant owner; the old token-name
substring no-op is removed. Brood's conditional and prototype branches retain
exactly one paid self-sacrifice ability producing one colorless mana. The
seven-row witness also checks P/T, colors, card types, subtypes, supertypes,
mana cost and exact ability inventories, including Cawl's vigilance.
These seven exact frozen bodies have independent direct/artifact blueprint and
native installation contracts. The installation witness fixes the count to one
to isolate name materialization; it is not a substitute for each full body's
existing payment, branch, trigger or quantity scenarios. They require this
reviewed correction and the next coordinated admission boundary before the old
and new definitions can be treated as equivalent. Eisenhorn's explicitly named
Cherubael remains Cherubael; its new retained role metadata still changes the
definition hash.

The generic Creature/Artifact/Vehicle/Enchantment description route now retains
roles in all three lowering entrances, including the fixed-count fast path.
That fast path previously bypassed role retention and name derivation; the
shared helper now owns its instruction envelope as well. Residual compact
templates, keyword-built creature templates such as Gift,
unproven reminder imports, mixed color-role fields, native omitted evidence,
quoted triggers without immutable definition stamps, and templates requiring
unmodeled attachment/spell/casting metadata remain explicit holds. This is not
full token-domain or full text-card coverage.

## Bounded predefined profiles

The typed `BuiltinTokenShape` selects the predefined definition and word roles.
Its implied colors, subtypes and abilities do not become literal words of the
creating instruction. Walker, Roles and the four card-name definitions retain
fixed names. Other predefined artifact/enchantment tokens derive subtype-plus-
`Token` names. Legacy abbreviated Spawn/Scion shapes retain unknown word roles;
their full descriptions use the ordinary authored owner above.

`ModifiedBuiltinTokenShape` retains explicit name/color/P/T/supertype/type and
keyword facts separately from the inherited template. Lowering keeps an ordered
inherited ability prefix and authored keyword/grant suffix, including a genuinely
additional ability equal to one of the inherited abilities. Duplicate parsing
of the same authored shape words is still reconciled within that authored part.
The wire/native effect envelope already carries the full role vector. Added
subtype words can overlap inherited values, so the present uniform subtype role
marks that mixed domain incomplete rather than treating its words as absent.
Native omitted roles, remaining keyword-built definitions, attachment-bearing
template traversal and unstamped nested triggers remain held. Presentation can
expand a predefined blueprint; its strings never reconstruct execution roles.

Eight exact previously proposed bodies require the corrected created names:
Aerid Konstrari, Hungering Puppetbeast and Tenured Tethermage create
`Heartwood Token`; Dora Milaje Elite, Shuri's Fabricator, T'Challa, the Black
Panther, The Great Mound and Vibranium Mining Mech create `Vibranium Token`.
Their complete frozen fixture is `fixtures/predefined_token_definitions.json.fixture`.
The canonical leaf selects a typed builtin, `build_builtin_token_definition`
selects `card_tokens.rs`'s complete definition, and the shared retention owner
corrects the name before native creation. Their existing full-body scenarios
now assert those names on independent direct and artifact routes while retaining
all entry conditions, payments, abilities, tap state, restrictions and tails.
The four card-name-token bodies keep their exact names. This bounded correction
does not imply an affected count for other token producers or any text-card credit.

## Authored evidence

Native contracts distinguish explicit and derived names, literal and implied
colors/abilities, missing/misaligned inventories, actual token creation, existing
token text changes, and copied creator spells. Direct/artifact/fresh-native codec
contracts retain roles through rewrite and rematerialization. Frontend contracts
cover names containing color/type/keyword words, quoted characteristic isolation,
Vehicle colors, and postnominal color forms. Existing reused-token contracts now
expect the migrated Alien Token name. No builds,
compilation, compiler probes, formatters, tests or engine/corpus execution ran.

Primary rules: Wizards' 2026-09-25 Comprehensive Rules,
https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.pdf,
111.3, 111.4, 111.10w/x, 111.11, 612.2a and 612.4. Neither the Heartwood nor
Vibranium predefined rule specifies an explicit name, so rule 111.4 applies.
The creation instruction derives names from subtype
words when no explicit name is given; changing an existing token's subtype does
not derive its name again.
