## Semantic composition

The numeric source branch hashed raw ability bytes before the newer normalized
first-draw, activation, and trigger construction owners existed. That would make
nested CardId allocations and already generated identities inputs to the new
combined namespace, or leave root trigger proof unavailable.

The integrated finalizer binds only the typed entry producer, explicit numeric
readers, and permitted reselection to a provisional numeric namespace. It then
uses the existing typed artifact graph normalizer with ephemeral numeric and
validated first-draw construction proof. Actual CardIds become graph ordinals;
shared and distinct generated definition groups remain distinct. The numeric
version-two domain freezes the resulting immutable pair, and its proof flows
alongside the first-draw proof to activation and trigger finalizers. Generated
root stamps are outputs, never feedback inputs. Re-finalization repeats the same
construction. Runtime/native acquisition IDs, existing live links, and unrelated
opaque pairs are neither erased nor reconstructed to force equality. An
unproven opaque input is an error for the new numeric construction.

This is a general integration prerequisite for the still-uncounted numeric
candidate. Previously counted first-draw-only bodies retain their existing
normalization path; no additional counted-body hold is introduced here.
