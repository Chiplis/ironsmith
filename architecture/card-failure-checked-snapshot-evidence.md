## Admission and production owners

`ObjectSnapshot::try_from_object_with_calculated_characteristics`, its supplied-
effects variant, and `try_from_object_with_known_characteristics` return the
original typed continuous-discovery error before assembling authoritative
snapshot evidence. The same admission applies to attachment characteristics.
A missing frame is unavailable evidence; it is never replaced with a printed
or empty snapshot. A complete never-chosen numeric acquisition still uses its
authored zero default, and completed zero/nonzero choices retain their value.

The bounded production migrations are:

- Token-copy source capture, public original-entry context, and entry batch
  pre-capture/completed entry capture.
- Destruction pre-capture, replacement redirection, and native zone proposals.
- Cached departure LKI before any zone mutation or exile-viewer removal.
- Whole-hand reveal compact memory after public opening/hydration.
- Completed spell-cast capture and resolving target snapshot admission.
- Trigger-source admission and trigger-to-stack projection. The checked discovery
  API owns a private failure scope when its read-only caller has no active meter.
- SBA pre-capture and legend-rule plans.

Frozen zone/destruction continuations keep a typed Result in their private
native envelope. Their existing fallible completion owner checks it before
using the frozen bindings. Capturing failure also reaches an active transaction's
incomplete-execution latch, preserving the original error if an infallible
intermediate helper drops an optional capture. No public/serialized snapshot
field or gameplay checkpoint is added.

Legacy Self-returning snapshot wrappers remain compatibility APIs with an
explicit complete-evidence guard. The listed production owners use checked
Results or the existing incomplete-execution latch and rollback; their closure
does not depend on panicking. This is a bounded migration, not a claim that every
legacy snapshot caller elsewhere in the engine has become fallible.
