# Bounded numeric choices (UNVALIDATED)

Two exact frozen source candidates: By Invitation Only and Expel the Interlopers.
The complete named clause/statement reader accepts an authored inclusive numeric
range. It emits a typed chooser action and core effect, not string options or a
label that drives execution. The runtime uses the ordinary number decision with
these exact bounds, rejects out-of-range responses, and publishes no chosen-number
fact before a pending decision completes. Zero is a successful numeric choice.

`PriorEffectAction::ChosenNumber` is appended to preserve serialized ordinal
compatibility. A reference to the chosen number binds to that exact numeric
producer, independently of intervening card or damage results. It cannot silently
use the newest object-choice count. The native payload has both artifact decoder
routes, card-graph mapping, lowering, reference visitors and typed rendering.

The engine's i32 outcome representation is checked explicitly before offering an
unsupported numeric range. This is an incomplete host calculation rather than a
clamped choice. Neither named candidate exceeds that representation.

Authored native tests cover endpoints, invalid response, pending choice and
representation errors. Strict direct/artifact full-card scenarios cover choosing
only during resolution, zero and large authored bounds, per-player sacrifice
availability, live power thresholds, indestructible and exact numeric references
across a draw. All tests are unrun; no builds, compiler probes or replay ran.

Persistent as-enters/reselection choices, arbitrary unbounded number choices,
number-as-additional-cost and their full secondary bodies remain distinct open
contracts. Shapeshifter, Talion, Sanctum Prelate, Void, Liquid Fire and Scrying Glass
are retained as explicit partial fixture entries and receive no coverage here.

Bounded review also required native-origin encoding, not just compiler-retained
metadata. ChooseNumberEffect now appears in the direct native schema vocabulary
and matching interpreter inventory. A fresh native encode/materialize/reencode
scenario checks the exact chooser and inclusive bounds; it remains unrun.
