## Six paired construction owners

Compiler and native `CardDefinitionBuilder` own complete token definitions for
Afterlife, Fabricate, For Mirrodin!, Job select, Living weapon and Mobilize.
Their private construction helper records `TokenTextRoles::rules_implied` with
an exact ability occurrence count and a subtype-derived name. The factories
provide Spirit Token, Servo Token, Rebel Token, Hero Token, Phyrexian Germ Token
and Warrior Token, respectively. No generic token constructor guesses provenance
from a finished card name, colors or abilities.

The keyword expansions keep their inherited colors/types/abilities through a
text change. Explicit parameter expressions remain traversable: changing Warrior
to Human in a Mobilize quantity filter changes what it counts, while the generated
tokens remain Warriors. Tagged creation and attachment, Fabricate's counter/token
choice, and Mobilize's tapped/attacking entry and delayed sacrifice are unchanged.
Existing tokens, immutable captured programs and copied values are not renamed.

The presentation recognizers use the retained implied-word profile with typed
characteristics. Token names no longer decide whether an expansion is Fabricate,
Living weapon, For Mirrodin!, Job select or Afterlife. Mobilize no longer compares
a rendered blueprint string. Ordinary authored descriptions retain their literal
word roles instead of being compressed into one of these implied expansions.

frozen bodies from the campaign corpus. Sixteen Job select equipment bodies use
the Hero factory: Astrologian's Planisphere, Bard's Bow, Black Mage's Rod,
Blue Mage's Cane, Dancer's Chakrams, Dragoon's Lance, Machinist's Arsenal,

Avenger of the Fallen and Infantry Shield use the dynamic Mobilize factory.
Their prior bare Hero/Warrior names were incomplete under CR 111.4. These are
source-proven naming repairs, not newly measured compilation or gameplay credit.

Norn's Inquisitor uses the separate Incubate/linked-face owner. Its bounded name
correction gives the front face the derived name Incubator Token and keeps the
back face's explicit Phyrexian Token name. Both directions of the linked name
metadata agree, while CardIds, costs, abilities and face links retain their
existing ownership. Native and complete direct/artifact Norn scenarios cover
creation counters, paid transformation, Norn's additional counter trigger, and
transformation back with the same counters and restored front name. This does
not admit broader text changes through double-face definition provenance.
Investigation of other keyword/native
constructors and immutable nested trigger definitions is not claimed here.
Investigate/Clue and Amass/Army are owned by the concurrent keyword-action repair.

## Authored contracts

Native tests inspect all six definitions and ordered ability inventories and
rewrite both generated characteristics and an explicit dynamic quantity filter.
Independent direct and artifact routes then encode/materialize the rewritten
native instruction and retain all lifecycle flags. A literal Spirit-creation
control remains editable and retains its ordinary presentation. Every frozen
Job select body queues and resolves its actual entry trigger and verifies the
created Hero Token and its attachment. Existing full Mobilize body scenarios
retain counts, paid equip, source departure, recipient changes and delayed expiry,
and now assert the exact created names. No scenario has been executed.

Primary source: Wizards' Comprehensive Rules, 2026-09-25,
https://media.wizards.com/2026/downloads/MagicCompRules%2020260925.pdf.
Rule 111.4 derives unnamed token names from subtypes plus Token. Rules 702.92,
702.123, 702.135, 702.163, 702.181 and 702.182 define the six keyword expansions;
their implied characteristics are not printed color/creature-type words of the
creating keyword. Text-changing rules 612.1–612.4 preserve that distinction.
