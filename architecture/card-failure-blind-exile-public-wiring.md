## Before opening

`PriorityActionRef::OpenExiledCardForPlay` carries only `card_id` and the existing
`GrantSelectionRef { source, index }`. The index belongs to the unqualified,
face-independent permission list. The adapter re-derives this exact action even
when a cached priority menu claims to be complete, and rejects a stale priority
owner, source, grant or incarnation. The admitted native selection retains its
immutable acquisition identity. No face, name, land/spell classification, target,
cost, affordability or alternative-casting selector is read to construct this
public reference or its label, which is always “Play exiled card”.

A dedicated read-only preview returns the exact card's `public_open` requirement
with pre-command timing, from hidden commitment metadata alone. Its `card` name
is omitted even on a peer whose engine knows the face. Preview never dispatches
the opening to discover requirements. This avoids both hidden-characteristic
proposals and circular execution against an unmaterialized placeholder. Existing
manifest, origin, shuffle and opening proofs still materialize the card before
native dispatch; hydration alone grants no private inspection right.

The ordinary identity helpers recognize the new reference. Its remapping uses
an exact hidden incarnation, not a stable-card fallback across later zone changes.
The full grant selector survives remapping and replay. Generic `select_options`
commands resume the native post-opening choice. The native typed
`exile_play_choice` marker distinguishes it from nested entry/replacement options,
which must replay the already chosen play rather than select another play.

## Irreversible disclosure and recovery

The native disclosure owner classifies the opening before material generation.
Its subject is the actual priority-team actor and original exile incarnation;
`opened_exile_play` preserves those through a spell's ObjectId change, targets,
additional costs and mana payment. A failed command restores a full runtime
savepoint and requires the identical normalized answer. Cancellation and Undo
remain blocked; ordinary nondisclosing cancellation retains its existing path.

The journal pins the original signed blind-opening intent before generating or
releasing reveal shares, even if there is not yet a complete face payload. This
conservatively commits a requested opening as the material protocol starts.
Empty-material recovery can therefore retain the same native opening against a
placeholder until authenticated material arrives. The accepted-head actor check,
original signed attempt, original public checkpoint and deadline are all retained.
A completed material response is proof-verified and required to match that exact
native opening before hydration/publication. Responder publication and actor
receipt both merge that evidence into the durable pin. Receipt-side native
recovery serializes concurrent material responses.

The direct Ziffle action-authorization route pins before releasing shares; the
outbound crypto-material route already has the actor's durable pin. The existing
volatile disclosure lock remains an additional guard, not the recovery owner.
Old accepted actions use their existing transcript authorization. Current blind
opening token authorization requires the original signed action intent.

Both local submission and incoming optimistic calculation consult native
disclosure classification before provisional claims can hydrate or display a
face. The committed action and its continuations use verified transport.

Failed-prefix restoration keeps only the exact disclosed source inspectable in
exile, including when card owner and announcing actor differ. It does not change
the accepted public game hash or grant an unrelated hidden-card inspection right.
Both native snapshot JSON and normal WASM snapshots overlay that public knowledge.
Native root, replay, inactive-lane and suspended-host savepoints clone the exact
receipt; public audit snapshots remain consensus projections with no importer.
Accepted-transcript replay is the other supported reconstruction route.

The public priority projection includes an optional opened-exile receipt with
original card/player, public grant selector and whether the initial option is
pending. Inactive grand-melee lanes use the same projection. No protocol or
artifact version is advanced here. The coordinator's final combined current-peer
and replay gate must cover the new command and projection before publication.

price, land allowance and alternative methods; exact and stale selectors;

spell completion; target and payment prompts with an unchanged transaction

JavaScript witnesses cover generic labels, selector preservation, mandatory public

responder/receiver proof and publication ordering, optimistic bypass, and rejecting
stable-card rebinding for opaque openings. These are authored expectations, not
reported successful executions. They supplement rather than replace browser,
multiplayer transcript and cryptographic integration execution.

The native correction restores the exact pre-opening game and trigger queue when
no legal play is available, including physical face-down status. Only the already
publicly learned identity of that exact exile incarnation is retained. Updated
adapter assertions require both face-down rules state and public inspectability;
no cast, land allowance, payment or permission use succeeds on this terminal path.
Technical command retries keep their after-opening continuation and disclosure
commitment. This follows the independent CR406.3a/733 source review; retaining
knowledge does not make the physical opening or an illegal play irreversible.

The mandatory-opening menu excludes FaceDownPlayFrom. Already inspected cards
retain their prior no-opening route. Genuine unseen face-down casting remains a
separate pending authority/claim owner; this adapter does not treat a public
opening as its substitute. Rogue remains uncounted pending that owner and final
native/adapter/protocol source clearance.
